Shared storage for mixed Windows and Linux workloads

Resilient Cloud Solutions

This question was generated by AI and may contain errors. Treat it as study support, not as an authoritative source.

A company runs Windows and Linux workloads on Amazon EC2 across several Availability Zones. Both fleets need the same shared file system with sub-millisecond latency, accessible over SMB and NFS. Which TWO options meet these requirements?

A

Deploy Amazon FSx for NetApp ONTAP in a Multi-AZ configuration and expose the volume over both SMB and NFS.

Comment

Correct: ONTAP serves the same volume over both protocols and Multi-AZ keeps it available.

B

Mount an Amazon S3 bucket on every instance with a FUSE driver.

Comment

Incorrect: object storage mounted through FUSE does not provide sub-millisecond file semantics.

C

Use Amazon FSx for OpenZFS for the Linux fleet and FSx for Windows File Server for the Windows fleet, with data kept in sync.

Comment

Correct: each fleet gets a native, low-latency file system for its protocol.

D

Attach a single Amazon EBS Multi-Attach volume to all instances in every Availability Zone.

Comment

Incorrect: EBS Multi-Attach is limited to a single Availability Zone.

E

Run an NFS server on a self-managed EC2 instance in one Availability Zone.

Comment

Incorrect: a single instance in one AZ is not highly available.

General comment

Both correct options give each operating system a native protocol with Multi-AZ availability; the distractors either lack the latency, the protocol support, or cross-AZ access.
